## Linux
1. **Какие ОС семейства Linux вы знаете? Какие ОС семейства Unix вы знаете? В чем отличие данных типов ОС?**  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Linux это ядро, на основе которого собирается система, Unix - семейство ОС. Примеры дистрибутивов Linux (linux-based system): Ubuntu, Debian, Arch, Kali linux, Fedora, Debian и т.д.. Unix-подобные системы: MacOS, FreeBSD, OpenBSD, NetBSD, Solaris и т.д.

2. **В каком файле хранятся локальные пользователи и пароли в Linux?**  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Локальные пользователи хранятся в файле /etc/passwd, раньше пароли лежали там же, но сейчас они вынесены в /etc/shadow из соображений безопасности.  
/etc/passwd — доступен для чтения всем  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - имя пользователя  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - UID / GID  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - домашнюю директорию  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - shell  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - поле пароля (но там обычно x)  
/etc/shadow — доступен только root  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - хэш пароля  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - информацию о сроке действия пароля  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - политику смены пароля    
<br>   
<br> 



4. **Как узнать права пользователя в Linux, какая группа даёт права локального администратора?**  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - **id username** - показывает UID, основную и дополнительные группы  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - **groups username** - список групп пользователя  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - **whoami** - текущий пользователь  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - **sudo -l** - какие команды можно выполнять с sudo  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; В Linux нет отдельного «локального администратора» как в Windows — доступ к правам root обычно даётся через sudo. В Debian/Ubuntu это группа sudo, в AlmaLinux — группа wheel. Пользователи из этих групп могут выполнять команды с правами root, это настраивается в /etc/sudoers или /etc/sudoers.d/

6. **Укажите каталог, в котором содержатся все журналы Linux**
Все журналы в Linux по умолчанию находятся в каталоге /var/log. Внутри:  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - системные логи (syslog, messages)  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - логи аутентификации (auth.log, secure)  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; - логи сервисов (nginx, ssh и т.д.)  
<br>

8. **В каком журнале присутствуют события аутентификации?**  
/var/log/auth.log  
Там лежат входы/выходы пользователей, SSH-логины, использование sudo
Если используется systemd - можно смотреть через journalctl (например, journalctl -xe или фильтровать по ssh/sudo).

9. **Как посмотреть содержание текстового файла?**  
  - cat file - вывести весь файл сразу

11. **Как найти все файлы с расширением .log?**

12. **Как сделать так, чтобы скрипт запускался периодически или в заданное время?**  
- cron - добавить задачу в crontab -e (например, 0 2 * * * /path/script.sh)  
- at - разовый запуск в заданное время (at 10:00)  
- systemd timers - альтернатива cron   
- Цикл в скрипте (while true; do ...; sleep 60; done) — периодический запуск внутри самого скрипта

13. **Не пускает по ssh под root на сервер, какие возможные проблемы?**  
- В конфиге SSH запрещён root: PermitRootLogin no в /etc/ssh/sshd_config
- Вход разрешён только по ключам: PasswordAuthentication no и нет корректного SSH-ключа
- root вообще запрещён для входа (например, через PAM или AllowUsers / DenyUsers)
- Неправильные права на ~/.ssh или authorized_keys
- Сетевые ограничения  
В общем стоит посмотреть конфиг sshd, ключи, права и логи (/var/log/auth.log или /var/log/secure)

14. **Как можно попасть на сервер по ssh, не вводя пароля?**

17. **Каким способом можно определить тип операционной системы хоста, не имея логического доступа к нему?**  
Во-первых по сетевым признакам:
- Сканирование через Nmap с -O - определяет ОС по TCP/IP-сигнатурам
- Анализ TTL в ответах (ping) - на линуксе ~64, для винды дефолтное значение ~128
- Анализ открытых портов и сервисов (nmap -sV) - по баннерам можно предположительно сделать вывод о системе. Например, типовыми для виндоус будут порты 135 (RPC), 139/445 (SMB), 3389 (RDP), для линукса - 22 (SSH), часто 80/443 (nginx), также нужно смотреть на названия сервисов, характерных для той или иной ОС

18. **Какие средства аудита (контроля целостности) в Linux вы знаете?**    
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Обычно используются либо утилиты сравнения хэшей (AIDE/Tripwire), либо системы аудита и HIDS (auditd, OSSEC). HIDS - это система, которая работает прямо на хосте и отслеживает изменения в системе и подозрительную активность, включая контроль целостности файлов. Утилиты типа AIDE/Tripwire создают эталонную базу хэшей файлов и при проверке сравнивают текущее состояние с эталоном, фиксируя любые изменения, удаления или добавления файлов.

19. **Протокол syslog и для чего он используется?**  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; *syslog* - это стандартный протокол и механизм, который собирает события системы и приложений, сохраняет их локально или отправляет на центральный сервер для анализа. По сути, это единый способ, через который разные компоненты системы пишут свои логи.  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Работает это так: есть сервис (например, rsyslog или syslog-ng), который принимает сообщения от системы, демонов и приложений. Каждое сообщение содержит информацию о том, откуда оно пришло (facility) и насколько оно важно (severity - от debug до critical). Дальше этот сервис решает, что с сообщением делать: записать в файл (обычно в /var/log), вывести в консоль или отправить на удалённый сервер.  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Syslog позволяет отправлять события по сети (обычно на порт 514 по UDP или TCP) на отдельный лог-сервер централизованно. Логи не теряются, их сложнее подделать на скомпрометированном хосте, и можно анализировать события сразу со многих машин.

20. **Как определить процесс, который больше всего использует системных ресурсов в текущий момент?**  
Проще всего использовать утилиту top, она показывает процессы, отсортированные по CPU (по умолчанию), или ps aux --sort=-%cpu | head, можно отфильтровать по используемой памяти %mem
<br>  
<br>  



21. **Как вывести все активные процессы? Как принудительно завершить процесс?**
Все активные процессы можно посмотреть с помощью ps aux (полный список процессов), или с помощью top. завершить процесс можно с помощью kill, для него нужно знать process id, ключ -9 выполняет принудительное завершение процессов. Команда killall завершает все процессы

23. **Для чего используется iptables?**  

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; iptables — это утилита, с помощью которой настраивают встроенный в Linux межсетевой экран (netfilter). По сути, она управляет тем, какой сетевой трафик разрешён, а какой блокируется  

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Работает это через правила фильтрации пакетов. Когда пакет приходит в систему или выходит из неё, он проходит через определённые цепочки (например, INPUT для входящего трафика, OUTPUT для исходящего, FORWARD для транзитного). В каждой цепочке есть набор правил, и пакет последовательно с ними сравнивается. Как только находится совпадение, применяется действие - например, разрешить (ACCEPT), заблокировать (DROP) или отклонить с ответом (REJECT)  

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; С помощью iptables можно управлять доступом: ограничивать подключения по IP-адресам, портам и протоколам, разрешать только нужные сервисы, блокировать трафик. Кроме того, он используется для NAT — например, когда нужно пробросить порт или скрыть внутреннюю сеть за одним внешним адресом.
