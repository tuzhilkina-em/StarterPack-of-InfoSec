## Какие порты нужны для связи от клиента до контроллера домена?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Все начинается с этапа обнаружения, система сначала должна найти доступный контроллер. Для этого используется DNS: клиент отправляет запросы к DNS-серверу и ищет SRV-записи, которые указывающие на DC. Это происходит по tcp/udp (port **53**)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; После того как контроллер найден, начинается этап аутентификации. В нормальной ситуации используется  Kerberos: клиент обращается к контроллеру домена за получением TGT (Ticket Granting Ticket), который затем используется для доступа к другим сервисам. Для этого взаимодействия применяется порт **88**. Если Kerberos по каким-то причинам недоступен, система может использовать NTLM


&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Далее клиент начинает работу с AD. Для этого используется протокол LDAP, через который выполняются запросы к объектам каталога: пользователям, группам, политикам. Обычно это происходит через порт 389, либо через 636, если используется защищённое соединение (LDAPS). Если требуется доступ к глобальному каталогу, например для поиска объектов по всему лесу, используются отдельные порты 3268 или 3269

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Параллельно с этим активно используется механизм RPC (Remote Procedure Call). Сначала клиент обращается к endpoint mapper на порту **135**, чтобы узнать, какие сервисы доступны на контроллере домена, после чего устанавливаются соединения через динамически выделяемые порты. Через RPC работают многие внутренние функции Active Directory, включая репликацию и часть административных операций

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; На следующем этапе клиент получает доступ к ресурсам домена, в первую очередь к групповым политикам. Для этого используется протокол SMB через порт **445**. Через него клиент обращается к каталогу SYSVOL на контроллере домена, откуда загружаются политики, скрипты входа и другие служебные данные, необходимые для корректной работы в домене.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Важным является также процесс синхронизации времени. Kerberos чувствителен к расхождению времени между клиентом и контроллером, поэтому используется протокол NTP через порт **123**. Без корректного времени аутентификация может завершаться ошибкой.
