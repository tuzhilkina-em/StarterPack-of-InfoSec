## Механизм PKINIT
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ***PKINIT (Public Key Cryptography for Initial Authentication in Kerberos)*** - это расширение Kerberos, позволяющее выполнять первоначальную аутентификацию не по паролю, а с использованием асимметрической криптографии и сертификатов. В обычном Kerberos пользователь подтверждает свою личность знанием пароля. KDC хранит производный ключ пользователя и использует его для проверки pre-authentication. При PKINIT вместо секрета, основанного на пароле, используется сертификат (врожде X.509) и приватный ключ клиента. PKINIT описан в [RFC 4556](https://datatracker.ietf.org/doc/html/rfc4556) и поддерживается Active Directory Certificate Services и Kerberos в Windows

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Пользователь вместо пароля использует сертификат и приватный ключ. Во время AS-REQ клиент отправляет контроллеру домена свой сертификат и цифровую подпись, созданную приватным ключом. KDC проверяет сертификат, доверие к центру сертификации, срок действия, отсутствие отзыва и соответствие сертификата учетной записи в AD. После этого KDC убеждается, что клиент действительно владеет приватным ключом, и только затем выдает Kerberos TGT. PKINIT не заменяет Kerberos полностью. Меняется только первоначальный этап аутентификации - AS exchange. После получения TGT вся дальнейшая работа остается обычным Kerberos: клиент запрашивает service tickets через TGS-REQ, использует PAC, SPN и session keys так же, как и при парольной аутентификации.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; В Active Directory PKINIT тесно связан с PKI-инфраструктурой. Контроллер домена должен иметь собственный сертификат KDC, обычно выданный через AD CS. На DC должен присутствовать сертификат с подходящими EKU, например Kerberos Authentication или Smart Card Logon, безз этого KDC не сможет обслуживать PKINIT-запросы. Для сопоставления сертификата с учетной записью Active Directory использует UPN, SAN или altSecurityIdentities. PKINIT работает через стандартный Kerberos-порт - TCP/UDP 88
