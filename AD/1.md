## Какие FSMO роли есть на контроллере домена и для чего каждая нужна?
В  FMSO пять основных ролей:
1.  *Schema Master* (Мастер схемы)
2.  *Domain Naming Master* (Мастер именования доменов)
3.  *RID Master* (Мастер относительных идентификаторов)
4.  *PDC Emulator* (Эмулятор PDC — Primary Domain Controller)
5.  *Infrastructure Master* (Мастер инфраструктуры)

## *Schema Master*
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Владелец роли является контроллером домена, ответственным за выполнение обновлений схемы, то есть контекст именования схем или LDAP://cn=schema,cn=configuration,dc=<domain>. Это единственный контроллер домена, который может обрабатывать обновления схемы каталога. После завершения обновления схема реплицируется из хозяина схемы во все остальные контроллеры домена каталога.   
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; В каждом лесу имеется только **один** хозяин схемы. Контроллеры домена и элементы леса обращаются к роли FSMO только при обновлении схемы.  
#### Важно
- Активен только в том случае, если с момента запуска службы каталогов владелец роли успешно выполнил входящую репликацию схемы контекста именования.
- Контроллеры домена и элементы леса обращаются к роли только при обновлении схемы.
    
Проще говоря: Schema Master управляет изменениями в схеме Active Directory (классы и атрибуты объектов)  
<br>  

## *Domain Naming Master*
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Владелец роли является ответственным за внесение изменений в пространство доменных имен на уровне леса каталога, то есть контекст именования секций\Конфигурации или LDAP://CN=Partitions, CN=Configuration, DC=<domain>. Это единственный контроллер домена, который может добавлять или удалять домены из каталога. Также он может добавлять или удалять перекрестные ссылки на домены во внешних каталогах.

#### Важно
- Активен только в том случае, если с момента запуска службы каталогов владелец роли успешно выполнил входящую репликацию конфигурации контекста именования.
- Члены домена леса обращаются к владельцу роли только при обновлении перекрестных ссылок. Контроллеры домена обращаются к владельцу роли в следующих случаях:    
  - Домены добавляются или удаляются в лесу.
  - Добавляются новые экземпляры разделов каталогов приложений на контроллерах домена. Например, DNS-сервер был включен в список разделов каталогов приложений DNS по умолчанию.

Проще говоря: Domain Naming Master управляет добавлением и удалением доменов в лесу, следит за уникальностью имен доменов в лесу, обрабатывает операции добавления/удаления доменов   
<br>  

## *RID Master*
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Владелец роли — это единый контроллер домена, отвечающий за обработку запросов пула RID  *(Relative Identifier)* от всех контроллеров домена в указанном домене. Он также отвечает за удаление объекта из своего домена и помещение его в другой домен во время перемещения объекта.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Если контроллер домена создает объект субъекта безопасности, например пользователя или группу, он присоединяет к объекту уникальный идентификатор безопасности (SID). Этот идентификатор безопасности включает:
- Идентификатор безопасности домена, одинаковый для всех идентификаторов безопасности, созданных в домене.
- Относительный идентификатор (RID), уникальный для каждого идентификатора безопасности субъекта безопасности, созданного в домене.  
  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Каждому контроллеру домена Windows в домене выделяется пул относительных RID, которые разрешено назначать созданным субъектам безопасности. Если выделенный пул RID контроллера домена оказывается ниже порогового значения, контроллер домена выполняет запрос дополнительных идентификаторов RID к хозяину RID в домене. Хозяин RID в домене отвечает на запрос, извлекая идентификаторы RID из невыделенного пула RID домена и назначая их пулу запрашивающего контроллера домена. Для каждого домена в каталоге имеется один хозяин RID.

#### Важно
- Активен только в том случае, если он успешно выполняет входящую репликацию доменного контекста именования с момента запуска службы каталогов.
- Контроллеры домена обращаются к владельцу роли FSMO при извлечении нового пула RID. Новый пул RID доставляется контроллерам домена через репликацию AD.  

Проще говоря: RID Master выделяет пулы RID (Relative ID) для контроллеров домена.


## PDC Emulator
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Эмулятор PDC необходим для синхронизации времени на предприятии. Windows включает в себя W32Time, службу времени, используемую протоколом проверки подлинности Kerberos. 

#### Важно
- Этот владелец роли FSMO всегда активен, если эмулятор PDC находит атрибут fSMORoleOwner доменного контекста именования, указывающий на себя.
- Контроллеры домена обращаются к владельцу роли, если у них есть новый пароль или при сбое проверки локального пароля.  

Mожно использовать для проверки предварительных требований для понижения уровня контроллера домена:
> PS C:\Users\Capecodadmin> Test-ADDSDomainControllerUninstallation -DemoteOperationMasterRole |fl

Проще говоря: выполняет следующие функции: обработка изменений паролей, синхронизация времени, блокировка учеток, реализация групповых политик. Кроме того он эмулирует поведение PDC для старых клиентов (NT4 и старше), а также управляет распределенной файловой системой


## *Infrastructure Master*
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Если на объект в одном домене ссылается другой объект в другом домене, он представляет ссылку по:
- Идентификатору GUID
- Идентификатору безопасности (для ссылок на субъекты безопасности)
- DN объекта, на который указывает ссылка
Владелец роли — контроллер домена, отвечающий за обновление идентификатора безопасности и различающегося имени объекта в ссылке на междоменный объект.
#### Важно
- Активен только в том случае, если он успешно выполняет входящую репликацию доменного контекста именования с момента запуска службы каталогов.
- Для этого владельца роли FSMO не требуется подключение. Это внутренняя функция очистки леса.

Проще говоря: Infrastructure Master отслеживает изменения ссылок и обновляет эти ссылки в своем домене  


Команды для просмотра ролей powershell:
> Get-ADDomain | Select-Object InfrastructureMaster, RIDMaster, PDCEmulator  
> Get-ADForest | Select-Object SchemaMaster, DomainNamingMaster  

Через терминал:
> netdom query fsmo   

Перенос ролей:
> Move-ADDirectoryServerOperationMasterRole -Identity "..." -OperationMasterRole ...
