## Как работает LDAPS

### Превьюшка про LDAP
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ***LDAP (Lightweight Directory Access Protocol)*** -  открытый протокол, используемый для хранения и получения данных из каталога с иерархической структурой. Обычно используется для хранения информации об организации, ее активах и пользователях, LDAP является гибким решением для определения любого типа сущностей и их свойств. Работает на прикладном уровне, сам по себе он не хранит никаких объектов и данных, а в AD используется для поиска в структуре каталогов AD (Directory Information Tree) нужных объектов  
<br>  

LDAP работает поверх TCP/IP, из основного: 
-  TCP/389 - обычный LDAP
-  TCP/636 - LDAP over SSL/TLS (LDAPS)
-  ТCP/3268 - Global Catalog 
-  ТCP/3269 - Global Catalog через SSL/TLS  
<br>  

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Когда необходимо получить информацию из AD, устанавливается LDAP-соединение с контроллером домена. После подключения обычно происходит **bind operation** - операция аутентификации.

Существует несколько типов bind:  
- ***Anonymous bind*** - подключение без учетных данных, в AD обычно ограничен или отключен
- ***Simple bind*** - передает логин и пароль. Без TLS пароль фактически уходит в открытом виде, поэтому simple bind без LDAPS считается небезопасным
- ***SASL bind*** использует механизмы Windows-аутентификации (Kerberos, ntlm, spnego), но чаще используется SASL/Kerberos
<br>   

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; После bind клиент начинает выполнять LDAP-операции (bind, **search**, compare, add, delete, modify, etc). Когда контроллер домена получает LDAP-запрос, запрос обрабатывает служба LSASS. Она взаимодействует с базой NTDS.dit - файлом базы Active Directory, где физически хранятся объекты каталога. Взаимодействие реализовано посредством LDAP-службы, Directory System Agent и ESE database engine

## LDAPS
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; LDAPS - это LDAP-соединение, работающее внутри TLS/SSL. Сам LDAP не меняется: меняется транспортный уровень. Вместо передачи LDAP-пакетов в открытом виде создается защищенный TLS-канал, внутри которого уже передаются bind-запросы, search-запросы и остальные LDAP-операции. Работает он на порту 636, а схема взаимодействия через LDAPS строится следующим образом: 
1. Client - TLS-Handshake: на этом этапе происходит проверка и подтверждение работы серта
2. Certificate Validation
3. Encrypted LDAP Session
4. Methods of LDAP

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Итого - LDAPS - то же что и LDAP, только через TLS - туннель, что обеспечивает защищенное соединение, в AD таже есть соответствующая gpo, разрешающая соединение только по LDAPS
