## Без каких сопутствующих компонентов не будет работать AD?
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Active Directory не будет функционировать без DNS, который необходим для поиска контроллеров домена и клиентов. Кроме того, важны работающие протоколы синхронизации времени (NTP/W32Time) для аутентификации Kerberos и наличие TCP/IP-сети для сетевого взаимодействия, ну и без электричесва кнч
### DNS
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Cистема доменных имен позволяет клиентам находить контроллеры домена, обеспечивает репликацию данных и аутентификацию, преобразуя имена узлов в IP-адреса, а также используя SRV-записи для поиска служб. основое его назначение заключается в следующем:
- Компьютеры находят контроллеры домена (DC) с помощью специальных SRV-записей, которые указывают, где запрашивать аутентификацию или применять политики
- Зоны DNS могут храниться непосредственно в базе данных AD, обеспечивая безопасную репликацию данных DNS между контроллерами домена

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; *SRV-записи (Service Records)* — это тип ресурсных записей в DNS, указывающих на местоположение (имя хоста и порт) серверов, обеспечивающих работу конкретных служб (SIP, LDAP). Они позволяют использовать нестандартные порты, балансировать нагрузку и повышать отказоустойчивость, определяя приоритет серверов   

Проверку регистрации DNS-записей контроллером можно выполнить так:
> dcdiag /test:dns /v

Получить SRV-записи:  
> nslookup -type=SRV _ldap._tcp.dc._msdcs.<domain>

### [DFSR](https://interface31.ru/post/vosstanovlenie-replikacii-sysvol-pri-pomoshhi-dfsr-v-active-directory/)
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ***DFSR - (Distributed File System Replication)*** - репликация распределенной файловой системы. Ответственным за внесение изменений в групповые политики и пространство имен DFS является эмулятор первичного контроллера домена - PDC, поэтому скорее всего именно он будет обладать наиболее актуальной копией, а отсюда следует что и без dc AD работать не будет.

### NTP/W32Time
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Служба времени Windows (w32time) использует протокол NTP для синхронизации часов всех компьютеров в домене Active Directory (AD), обеспечивая точность, необходимую для работы Kerberos-аутентификации, репликации и журналов безопасности. Иерархия AD требует, чтобы все клиенты синхронизировались с контроллерами домена, а PDC-эмулятор — с внешним надежным источником
