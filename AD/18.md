## Где храниться AD на файловом уровне 'каталог'?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Все данные каталога Active Directory хранятся в БД в файле **ntds.dit**. Подавляющее большинство приложений взаимодействуют с каталогом через прослойку DSA реализованную в ntdsa.dll. В свою очередь функции из ntdsa.dll не работают напрямую с ntds.dit, их функционал ограничен потребностями службы каталогов и они не могут дать нам представление о внутреннем устройстве БД Active Directory. Тем не менее ntds.dit представляет собой не что иное как БД JET Blue. В каждой версии windows (начиная с Windows 2000) есть всё необходимое для работы с ней


&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Внутри базы данные организованы по принципу directory store. Основной уровень - это разделы (naming contexts). В стандартной конфигурации их несколько:  
- ***Schema partition*** хранит описание всех объектов и их атрибутов. Любой объект в AD существует только потому, что его тип описан в схеме  
- ***Configuration partition*** содержит служебную информацию о всей инфраструктуре: сайты, подсети, сервисы, топология репликации. Этот раздел общий для всего леса  
- ***Domain partition*** - эпользователи, группы, компьютеры, OU. У каждого домена такой раздел свой  
Дополнительно есть разделы приложений (*application partitions*), которые используются, например, для интеграции DNS


&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; На уровне хранения внутри NTDS.dit каждая запись представлена как объект с набором атрибутов. Физически это реализовано через таблицы ESE, где есть строки (объекты) и колонки (атрибуты). Для быстрого поиска используются индексы, например по sAMAccountName, GUID или SID  


&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Отдельно стоит сказать про хранение паролей. В открытом виде их там нет. Для каждого пользователя хранится набор хэшей (NT hash и дополнительные значения для Kerberos). Эти данные защищены системными ключами, связанными с контроллером домена. При этом сама база NTDS.dit не может быть просто скопирована и прочитана без дополнительных ключей и контекста системы, в частности, ее состояние должно быть актуальным. Отдельный компонент - SYSVOL, который не входит в NTDS.dit, но логически связан с каталогом. В нём лежат GPO и скрипты. В отличие от базы, SYSVOL реплицируется на уровне файлов (через DFSR), а не через механизм каталоговой репликации
