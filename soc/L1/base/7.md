## Что такое протокол DHCP
*DHCP (Dynamic Host Configuration Protocol)* — протокол [прикладного уровня](https://github.com/tuzhilkina-em/StarterPack-of-InfoSec/blob/74fb224f64510e0182fd0e52e9f9476deff23467/soc/L1/base/1.md) динамической настройки узла, позволяющий устройствам автоматически получать IP-адрес, данные о DNS-сервере и другие параметры, необходимые для работы в сети.  

### Принцип работы протокола  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; При использовании DHCP весь процесс автоматизирован и управляется централизованно. DHCP-сервер поддерживает пул IP-адресов и арендует адрес любому клиенту с поддержкой DHCP при запуске в сети.  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Администратор сети устанавливает DHCP-серверы, которые поддерживают сведения о конфигурации TCP/IP и предоставляют конфигурацию адресов клиентам с поддержкой DHCP в виде предложения аренды.
Работа этого протокола осуществляется по принципу **DORA**:
- *Discovery* - После подключения клиент посылает сообщение DHCPDISCOVER на все устройства в локальной сети. В той же сети находится DHCP-сервер (например, Wi-Fi-роутер);
- *Offer* - DHCP-сервер отвечает на поиск предложением, он сообщает клиенту IP-адрес, который может ему подойти;
- *Request* - Клиент получает предложенный IP-адрес и отправляет на сервер сообщение DHCPREQUEST. Этим сообщением он принимает предлагаемый адрес и уведомляет DHCP-сервер об этом.
- *Acknowledgement* - Сервер получает от клиента DHCPREQUEST и окончательно подтверждает передачу IP-адреса клиенту сообщением DHCPACK. Оно утверждает не только владельца IP-адреса, но и срок, в течение которого клиент может использовать этот адрес.  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Может показаться, что этапы Offer и Request избыточны, а DHCP-сервер мог бы сразу назначить устройству адрес. Однако они поддерживают стабильность системы: гарантируют, что адрес уникален, настройки согласованы, а конфликты исключены. Например, в сети может быть несколько DHCP-серверов, и без этих этапов каждый бы назначал устройству адрес.

### Распределение IP адресов
В DHCP существует три способа распределения IP-адресов:
- Ручное распределение. Системный администратор назначает каждому устройству (например, по MAC-адресу) определённый IP-адрес. Эти параметры хранятся централизованно (на сервере DHCP) и используются при каждом подключении устройства к локальной сети.

- Автоматическое распределение. При подключении к локальной сети устройству для постоянного использования выделяется произвольный (свободный) IP-адрес из определённого администратором диапазона.

- Динамическое распределение. IP-адрес выдаётся устройству на определённое время (срок аренды IP-адреса). По окончании этого периода IP-адрес вновь считается свободным.

### Атаки на DHCP
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Одной из известных атак является так называемая DHCP Starvation. Злоумышленник рассылает большое количес­тво сооб­щений DHCPDISCOVER (запрос IP-адреса) в локальной сети с целью «исто­щить» адресное прос­транс­тво на сер­вере DHCP. Обрабатывая вал запросов, сервер выходит из строя и боль­ше не может обслу­живать новых кли­ентов в сети.  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Пос­ле этого зло­умыш­ленник создает фейковый DHCP-сервер в сети (DHCP Spoofing), заявив, что имен­но он и явля­ется сервером по умол­чанию (легитимным сервером). Теперь при подключении к локальной сети новые клиенты получают конфигурацию от фейкового сервера. Таким образом можно проводить атаки типа MITM (атака посредника), перехватывая тра­фик клиента.
