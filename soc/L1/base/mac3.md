## Основные элементы защиты macOS

### File Quarantine
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; **File Quarantine** - исторически один из первых механизмов защиты macOS. Принцип основан на том чтобы помечать загруженные из интернета файлы и требовать дополнительного подтверждения перед их запуском. File Quarantine срабатывает, когда пользователь загружает контент за пределами App Store, например, при помощи таких приложений, как браузер или торрент-клиент. При этом приложение добавляет специальную пометку в метаданные файла. По сути, это аналог Mark-of-the-Web в Windows

### Gatekeeper
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Поверх File Quarantine работает **Gatekeeper**, который проверяет, что по умолчанию на компьютере Mac пользователя запускается только надежное по. Когда пользователь загружает и открывает приложение, плагин или пакет установщика, полученный не через App Store, Gatekeeper проверяет, получено ли это программное обеспечение от подтвержденного разработчика, заверено ли оно Apple как не содержащее известного вредоносного контента и не было ли оно изменено. Gatekeeper также запрашивает согласие пользователя перед первым открытием загруженного программного обеспечения

Все приложения из App Store помещаются в песочницу, что ограничивает для них доступ к данным, хранящимся в других приложениях. Если приложению из App Store требуется доступ к данным другого приложения, оно может получить его только при помощи API и служб, предоставляемых macOS

### XProtect
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; По-сути, это авпо, работающее в фоне, статичнский список yara-правил. Их можно найти на компьютере через locate XProtect.yara. В дополнение к этому файлу существует еще набор списков свойств (plist). Например, XProtect.meta.plist - черный список плагинов Safari и gk.db и черный список приложений. Предназначено по для сигнатурного анализа, но, к сожалению бесполезно при таргетированных атаках тк обходится базово: обфускация

### TCC 
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; **TCC (Transparency, Consent, and Control)** представляет собой набор баз данных SQLite, которые используются для контроля доступа приложений к различным сервисам и функциям компьютера. Одна база находится в корневом каталоге (/Library/Application Support/com.apple.TCC/TCC.db), еще одна располагается в библиотеке у каждого пользователя (~/Library/Application Support/com.apple.TCC/TCC.db). Базы содержат информацию о том, какие функции компьютера доступны конкретным приложениям, и когда пользователь дал или отозвал свое разрешение на такой доступ. В теории, получив полный доступ к диску (FDA), злоумышленник может отредактировать базы TCC и обойти этот механизм, но для этого необходимо отключить SIP  


### SIP
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; **SIP (System Integrity Protection)** - это механизм, ограничивающий изменение критичных частей системы даже для пользователя `root`. В обычной Unix-модели он имеет почти полный контроль над системой, а в macOS это ограничено: процесс с root-правами не может свободно изменять защищенные системные файлы, директории и некоторые процессы, если это запрещено SIP  

SIP защищает системные области вроде /System, части /usr, /bin, /sbin, а также некоторые системные приложения и процессы. Исключение обычно сделано для путей, предназначенных для пользовательского ПО, например /usr/local. Работает это на уровне ядра. То есть ограничение не зависит только от файловых прав, даже если у файла формально есть права, и команда запущена через sudo, операция может быть заблокирована политикой SIP 

Проверить статус SIP можно командой:  
```bash
csrutil status
```

Отключение или изменение SIP выполняется не из обычной загруженной системы, а из recovery-среды
